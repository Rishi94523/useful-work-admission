# First physical iPhone 15 result

The user ran the explicit-start LAN page in Safari on their base iPhone 15.
All six independently seeded 64k FA10 crystal-input runs completed successfully.
Independent SHA256 checks of each uploaded raw pose pool and execution trace
matched the Node reference exactly, as did the WASM binary hash. This is a useful
cross-browser replay result for these six inputs, not proof of equivalence for
every molecule or device.

| Measurement | iPhone 15, Safari | Ryzen laptop, headless Chrome |
|---|---:|---:|
| Initialization after factory instantiation | 9.641 s | 3.023 s |
| Factory instantiation, excluding static import | 1.579 s | 0.013 s |
| Six warm 64k calls, range | 0.498–0.553 s | 0.317–0.385 s |
| Median warm call | 0.532 s | 0.362 s |
| All six calls combined | 3.176 s | 2.151 s |
| Total recorded elapsed time | 15.476 s | 5.221 s |
| Maximum observed allocated WASM memory | 42.7 MiB | 42.7 MiB |
| Exact raw pool and trace matches | 6/6 | 6/6 |
| Hidden-tab events | 0 | 0 |

The phone's measured main-thread animation-frame gaps were 33ms median and 35ms
maximum. That supports absence of a large frame stall during this run; it is
not a full interaction or display-performance study. No phone process-resident
memory, battery drain or temperature was measured. One successful six-run trial
does not establish sustained thermal behavior or old-device support.

The user entered OS version `26.5.2`. The recorded user agent contains both
`CPU iPhone OS 18_7` and `Version/26.5.2`; retain both as raw metadata without
inferring a verified OS version from either string.

## Interpretation

Warm execution of these short units fits the intended 200ms–1.5s range. Cold
startup does not: initialization alone takes 9.64s, and the full six-run visit
takes 15.48s. Task calls occupy only 20.5% of that total. This is a task-call
fraction, not a claim that receptor preparation has no scientific value.

The key mobile blocker in this test is startup amortization, not failure to
execute a short unit or growth in the measured allocated heap. Reusing an
already initialized worker for subsequent contributions is promising within a
session, but persistence across navigation or browser suspension is not measured.
Caching the downloaded WASM alone cannot be assumed to remove receptor/table
initialization. No new optimization or architectural change is made here.

The larger ranking comparison uses 256k medium units. This phone test uses 64k
units, so it does not yet demonstrate that the scientifically evaluated medium
workload fits the short phone visit budget. Do not extrapolate a measured 256k
latency from this test or call the deployed admission flow mobile-ready.

Next device evidence should measure a 256k unit, repeated cold and reused-worker
sessions, and at least one additional independent device if available. The
existing desktop and this iPhone now provide two physical hosts, with one trial
each and different browser engines. Ranking and admission integration remain
separate outstanding work.
